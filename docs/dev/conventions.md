# Конвенції коду

Повний текст — у
[`.claude/skills/swift_conventions/`](https://github.com/s-rybak/barosense/blob/main/.claude/skills/swift_conventions/SKILL.md).
Тут — те, що впливає на читання кодової бази щодня.

## Межі модулів

```
Shared/           доменні моделі, сервіси сенсорів, feature engineering.
                  Без UI. Має компілюватись і тестуватись без пристрою.
Barosense/        iOS-в'юшки + iOS-специфічна обв'язка.
BarosenseWatch/   watchOS-в'юшки + watchOS-специфічна обв'язка.
Tests/            XCTest.
```

Жорсткий наслідок: у `Shared/` немає `import SwiftUI`, `import UIKit`, `import WatchKit`.
Перевірка перед комітом:

```bash
grep -rnE '^import (SwiftUI|UIKit|WatchKit)' Shared/
```

Забезпечується **протоколами, а не дисципліною**: кожен сенсор, сховище й мережевий клієнт
сидять за протоколом, оголошеним поруч зі своїм споживачем, а справжня реалізація
інжектиться на рівні застосунку.

## Конкурентність

`SWIFT_STRICT_CONCURRENCY: complete`. Ворнінги тут — це майбутні помилки; їх не глушать.

- `async`/`await` та актори. Нових Combine-пайплайнів немає. Легасі-API з колбеками
  (`CMAltimeter`, `HKObserverQuery`) загортається **один раз, на межі**, в `AsyncStream`
  або `withCheckedContinuation`, і колбек не проникає далі.
- Типи, що перетинають межу ізоляції, — `Sendable`. Перевага типам-значенням; якщо межу
  має перетнути посилальний тип, він стає `actor`.
- `@MainActor` — на в'ю-моделях, **ніколи** на доменній логіці в `Shared/`.
- Ніколи `Task { @MainActor in … }`, щоб замазати ворнінг ізоляції — виправляється
  власність.

## Стиль

| Правило | Чому |
| --- | --- |
| Немає force-unwrap, `try!`, `as!` поза тестами | `guard let … else { return }` або типізований `throws`. SwiftLint: **error** |
| Помилки — типізовані `enum` на підсистему | Не `NSError` і не `String` |
| Публічний API кожного типу в `Shared/` документований `///` | Внутрішній код документується там, де неочевидне **чому**. Не переказувати, що робить код |
| Імена називають одиницю, коли вона неоднозначна | `pressureHPa`, `deltaHPaPer6h`, `windowSeconds` — не `pressure`, не `delta` |
| Одна одиниця в доменному шарі: **hPa** | `CMAltitudeData.pressure` приходить у кПа — конвертувати на межі сенсора, один раз |
| Feature-флаг на все, що змінює вихід прогнозу | Щоб вимкнути без релізу |

### Розміри

| Метрика | Warning | Error |
| --- | --- | --- |
| Довжина файлу | 900 | 2000 |
| Довжина тіла функції | 200 | 400 |
| Довжина рядка | 120 | 180 (URL ігноруються) |

Тіло `View` розбивається на підв'ю вище ~200 рядків.

## Бюджет дифа

Це те, що найчастіше порушують ненавмисно.

| Метрика | М'який ліміт | Жорсткий ліміт |
| --- | --- | --- |
| Змінені рядки (±) | 900 | **2000** → розділити задачу |
| Торкнутих файлів | 10 | **15** → розділити задачу |
| Нових сторонніх залежностей | 0 | **0** (гейтовано завжди) |
| Видалено публічного API | 0 | **0** без ADR |

```bash
git diff --stat main...HEAD | tail -1
```

Перевищити м'який ліміт **не заборонено** — потрібен один рядок у тілі PR, який пояснює
чому («згенеровані дані фікстури, 400 рядків, без логіки»). Перевищити жорсткий означає,
що задач насправді дві.

## Поза скоупом за замовчуванням

Це не робиться попутно, **навіть коли це очевидно правильно**:

- переформатування чи перенесення рядків у файлах, які й так не змінювались — включно з
  Markdown. Whitespace-only диф ховає справжню зміну від ревʼю;
- перейменування символів, файлів, тек;
- оновлення залежностей, версії Swift, deployment target;
- «полагодити» сусідній код не на шляху поточної зміни;
- додати абстракцію під другий випадок, якого ще не існує;
- видалити код, який **виглядає** мертвим, не довівши, що на нього немає посилань.

!!! tip "Як довести, що код мертвий"
    Сторінка [Гарячі точки](../reference/hotspots.md) генерується з індексу звернень і має
    розділ «Нуль звернень». Це **не** список мертвого коду — там же й точки входу з
    `@main`, методи протоколів, `body` у SwiftUI, `#Preview`, App Intents, — але це
    правильне місце, з якого починати доведення.

Знайшли щось із цього списку і воно варте роботи — заведіть issue або запишіть у
`Follow-ups`. **Не** лишайте `// TODO` у коді як запис.

## Документування

Публічний API `Shared/` документується `///`. Це не церемонія: **саме ці коментарі стають
[довідником API](../reference/index.md)** — генератор витягує їх із коду.

Тому працює просте правило: якщо опис у довіднику виглядає порожнім, це видно на
згенерованій сторінці як явний рядок «Без doc-коментаря в коді».

Що писати:

- **чому**, а не що. Код і так каже, що він робить;
- одиниці, діапазони, напрямок шкал;
- що станеться на пропуску даних;
- посилання на номер параграфа специфікації, коли значення звідти;
- слово «провізорно», коли число обрано з міркувань, а не з даних.

## Коміти й PR

Процедура — [`github_pr`](https://github.com/s-rybak/barosense/blob/main/.claude/skills/github_pr/SKILL.md).

```bash
/pr-prepare
```

Ця команда проганяє всі pre-PR гейти, складає тіло PR — **і зупиняється**. Нічого не
залишає машину без явного «так».
