# Журнал архітектурних рішень

ADR фіксує рішення, яке **дорого відкотити** і яке інакше довелося б реконструювати з
коду. Не кожна зміна потребує ADR; потребують ті, де важливий контекст помирає разом із
тредом обговорення.

## Коли ADR обов'язковий

| Ситуація | ADR |
| --- | --- |
| Увімкнення CloudKit або будь-якої синхронізації даних про здоров'я | **так** |
| Додавання бекенду чи мережевого адресата, окрім WeatherKit | **так** |
| Додавання сторонньої залежності | **так** (плюс гейт схвалення людиною) |
| Видалення публічного API | **так** |
| Зміна порога мітки (`poorWellbeingThreshold`) | **так** — знецінює кожну збережену метрику |
| Зміна одиниці або напрямку шкали | **так** |
| Додавання типу HealthKit | ні, але гейтовано процедурою `healthkit_permissions` |
| Новий засіб пробудження (таймер, `BGTask`, observer) | ні, але потрібен рядок battery note зі вартістю |
| Звичайна фіча в межах бюджету дифа | ні |

## Шаблон

```markdown
# ADR-NNNN: <рішення однією фразою>

- **Статус:** запропоновано | прийнято | замінено ADR-MMMM
- **Дата:** РРРР-ММ-ДД
- **Стосується:** <підсистема, файли>

## Контекст

Що змусило приймати рішення. Обмеження, які діяли на той момент. Числа, якщо вони були.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
| --- | --- | --- |

## Рішення

Що обрано. Одним абзацом.

## Наслідки

Що тепер простіше, що складніше, що доведеться переробити, якщо рішення скасують.
Що саме доведеться переміряти.
```

## Наявні записи

!!! info "Поки порожньо"
    Записів ADR ще немає. Рішення, які **вже** прийняті і які варті ADR заднім числом,
    зараз живуть у `///`-коментарях коду і в двох специфікаціях:

    - CloudKit вимкнено — [`BarosenseModelContainer`](../reference/Shared/Persistence/SwiftData/BarosenseModelContainer.md)
    - Барометр семплить телефон, а не годинник — [`ml-spec.md` § battery notes](https://github.com/s-rybak/barosense/blob/main/.claude/context/ml-spec.md)
    - Дві стадії ризик-моделі замість однієї — [`WellbeingRiskModel`](../reference/Shared/Risk/WellbeingRiskModel.md)
    - Чотири окремі контейнери SwiftData — [База даних](../database/index.md#чотири-окремі-бази-а-не-одна)
    - Зв'язки без `@Relationship` — [База даних](../database/index.md#звязки-підтримує-код-а-не-relationship)
    - Двогодинне вікно ризику — [`RiskWindowGeometry`](../reference/Shared/Risk/RiskWindowGeometry.md)

    Перенести їх у формат ADR — окрема робота, а не побічна дія іншої зміни.
