# Barosense

**Персональний трекер метеочутливості для iPhone та Apple Watch.**

Barosense збирає атмосферний тиск із вбудованого барометра iPhone, зіставляє його з
короткими самозвітами про самопочуття і будує **індивідуальну** модель того, як зміни
погоди корелюють із вашим станом. Коли модель бачить характерний для вас патерн —
надсилає завчасне сповіщення.

> Barosense — застосунок для відстеження особистих патернів самопочуття. Він не є
> медичним пристроєм, не ставить діагнозів і не замінює консультацію лікаря.

## Ідея

Метеозалежність — суб'єктивна. Хтось реагує на різке падіння тиску, хтось на затяжний
низький, хтось узагалі не на тиск, а на недосип. Універсальні «погодні прогнози для
метеозалежних» тому й марні: вони усереднюють людей, які реагують по-різному.

Barosense не намагається вгадати "загальну" реакцію. Він навчається **на вашій власній
історії** — і чесно показує, коли даних ще замало для висновків.

## Ключові фічі

**1. Індивідуальний прогноз самопочуття** — головна цінність продукту

On-device модель на ознаках: тиск із барометра iPhone (найбільша вага), погодні дані,
тривалість сну, кількість пробуджень, час від пробудження, пульс, SpO₂ → ймовірність
погіршення стану.

Модель — логістична регресія з калібруванням Платта, написана на Swift
(`Shared/Risk/`), а не Core ML. Навчання і оцінювання — forward-chaining, повністю на
пристрої. Core ML і `MLUpdateTask` свідомо не використовуються: обґрунтування — у
`Shared/Risk/LogisticRegressionModel.swift`.

**2. Застосунок на Apple Watch**

Поточний тиск, тренд і стан ризику на годиннику, плюс швидкий чек-ін звідти.

> Ускладнення (complication) на циферблаті — **заплановане, ще не реалізоване**. Коду
> WidgetKit у репозиторії поки немає.

**3. Збір тиску з `CMAltimeter`**

iPhone має справжній барометр. Дані знімаються локально, з урахуванням
бюджету батареї.

**4. Швидкі опитування**

≤10 секунд на введення: шкала інтенсивності 1–10 плюс теги (`головний біль`, `втома`, `суглоби`).
Це — розмітка, на якій навчається модель. Без неї прогнозу немає.

**5. WeatherKit**

Тренд тиску на 24–48 годин уперед. Барометр знає, що зараз; WeatherKit — що буде.
Саме це робить можливим _випереджувальне_ сповіщення, а не констатацію факту.

**6. Опційні сигнали з HealthKit**

HRV, пульс спокою, SpO₂ — додаткові ознаки для моделі. Дозволи запитуються точково: лише
те, що реально використовується.

## Приватність

- **Backend відсутній.** Уся обробка — на пристрої.
- Дані про здоров'я та самозвіти не залишають iPhone і Apple Watch.
- Модель навчається локально, у процесі застосунку.
- Єдиний мережевий трафік — запити до WeatherKit. Вони несуть координату, огрублену до
  0,1° (~11 км), і час — і жодного значення, похідного від даних про здоров'я.
- **Синхронізації між пристроями немає.** CloudKit вимкнено в коді
  (`cloudKitDatabase: .none` у `BarosenseModelContainer`), а не просто не налаштовано.
  Увімкнення потребує окремої явної згоди користувача та ADR — див. `docs/adr/`.
- **Бази виключені з резервних копій** iCloud та iTunes
  (`isExcludedFromBackup` у `BarosenseModelContainer.storeURL`). Інакше історія чек-інів
  потрапляла б в iCloud користувача силами системи, без запиту й без згоди.
  Зворотний бік цього рішення: **при переїзді на новий iPhone історія не переноситься.**
  Перенесення має бути явним експортом за згодою — його ще не реалізовано.
- Дані видаляються повністю: `Shared/Persistence/BarosenseDataEraser.swift`.

## Технологічний стек

| Область        | Технологія                             |
| -------------- | -------------------------------------- |
| Мова / UI      | Swift, SwiftUI                         |

## Документація

Повна технічна документація зібрана як сайт на **Material for MkDocs**:

```sh
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r docs/requirements.txt
.venv-docs/bin/mkdocs serve
```

Що там є:

- огляд системи, архітектура й потік даних з діаграмами;
- опис кожної підсистеми: тиск, погода, здоров'я, ризик, сповіщення, годинник,
  підписка, звіти;
- схема бази даних з ER-діаграмою — **генерується з `@Model`-класів**, тому не старіє;
- ML-конвеєр: дві мітки, реєстр ознак, протокол валідації, виміряні метрики;
- **довідник API**: сторінка на кожен `.swift`-файл із описом кожного типу, методу й
  властивості — і списком **усіх місць, де це ім'я використовується**, з посиланнями.

Довідник, схема БД, дерево репозиторію і граф модулів **не пишуться руками**: їх будує
`scripts/docs/generate_reference.py` при кожній збірці сайту.

```sh
.venv-docs/bin/python scripts/docs/generate_reference.py   # без запуску сервера
```

## Збірка

`.xcodeproj` **не зберігається в репозиторії** — він генерується з `project.yml`.
Це прибирає merge-конфлікти в проєктному файлі.

```sh
brew install xcodegen     # одноразово
xcodegen generate         # створює Barosense.xcodeproj
open Barosense.xcodeproj
```

Після додавання нового таргета або кореневої теки — перегенеруйте проєкт. Додавання файлу
всередину наявної теки перегенерації не потребує.

Для WeatherKit і HealthKit потрібен платний Apple Developer акаунт та налаштований App ID
з відповідними capabilities. Барометр не працює в симуляторі — тестування збору тиску
можливе лише на фізичному iPhone.
